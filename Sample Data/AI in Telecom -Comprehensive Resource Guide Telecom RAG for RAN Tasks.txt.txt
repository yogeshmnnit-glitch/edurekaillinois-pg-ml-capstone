## 7. RAG Frameworks & Reference Architectures

### 7.1 Telco-RAG — The Reference Implementation
| Field | Details |
|-------|---------|
| **GitHub** | [github.com/netop-team/Telco-RAG](https://github.com/netop-team/Telco-RAG) (72 ⭐) |
| **Paper** | [arXiv:2404.15939](https://arxiv.org/abs/2404.15939) |
| **Knowledge Base** | 3GPP standards documents |

**Architecture:**
```
User Query
  → [1] Glossary Enhancement (3GPP abbreviation expansion)
  → [2] NN Router (classifies which of 18 3GPP series to search)
  → [3] Retrieval-1 (preliminary context for query refinement)
  → [4] Candidate Answer Generation (query clarification)
  → [5] Retrieval-2 (final retrieval on selected series)
  → [6] LLM Generation (with source attribution)
```

**Optimal Hyperparameters (from paper):**
- Chunk size: **125 tokens** (smaller is better for technical docs)
- Embedding model: **text-embedding-3-large** (outperforms ada-002)
- Index: **FAISS IVF** with flat quantizer
- Retrieved context: 5 chunks
- Performance: **73.3% accuracy** on TeleQnA Standards Specifications

## Appendix B: Key Findings from Literature

1. **Chunk size matters:** 125 tokens outperforms larger chunks for technical telecom documents (Telco-RAG)
2. **Glossary enhancement critical:** Expanding 3GPP abbreviations before embedding improves retrieval by 5-10% (Telco-RAG)
3. **NN routing helps:** Classifying queries to relevant document subsets reduces noise significantly (Telco-RAG)
4. **IAPT can match DAPT+IAPT:** You may not need expensive continual pretraining; instruction tuning alone can be sufficient for RAG (TelcoLM)
5. **RAG outperforms fine-tuning alone:** GPT-3.5+RAG (69.8%) beats GPT-4 standalone (64.8%) on standards specs (TeleQnA)
6. **Chain-of-thought helps RCA:** Explicit reasoning chains improve root cause analysis accuracy (TeleLogs paper)
7. **Hybrid retrieval is essential:** BM25 + dense retrieval with reciprocal rank fusion outperforms either alone (Telco-DPR)
8. **QLoRA is sufficient:** ORANSight achieves SOTA with 4-bit QLoRA fine-tuning — no need for full fine-tuning (ORANSight)

### Metrics Implementation
```python
# MRR (Mean Reciprocal Rank)
def mrr(retrieved_docs, relevant_doc):
    for i, doc in enumerate(retrieved_docs):
        if doc == relevant_doc:
            return 1.0 / (i + 1)
    return 0.0

# Top-K Accuracy
def top_k_accuracy(retrieved_docs, relevant_doc, k=5):
    return 1.0 if relevant_doc in retrieved_docs[:k] else 0.0
```
